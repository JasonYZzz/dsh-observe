# dsh-observe 0.2.2 中文显示与日志搜索分析

## 核心结论

截图中的搜索属于运维诊断筛选，不是会话全文检索。0.2.1 的提示和入口不足，容易将原生会话事件、模型/工具正文与 Cordis 诊断输出混为一谈。

本次改动前只读检查用户正在运行的观测库：运维日志共 122 条，错误 5、警告 109、信息 8；带会话、轮次或节点关联的记录均为 0。这解释了截图中“会话日志”始终为空：有全局诊断输出，但没有可证明属于当前会话的记录。不是关键词没有触发请求，也不能通过按时间推测归属来修复。

## 原有行为与边界

| 项目 | 实际行为 |
| --- | --- |
| 数据来源 | 插件运行时的 Cordis Logger 导出，以及 agent/error 事件；不是 Session 消息正文 |
| 级别 | 错误、警告、信息；debug 不采集 |
| 会话关联 | 需要明确 sessionId，或已知 agentId；轮次还需要 turn，工具节点还需要 step/callId；仅在参数文字中出现会话 ID 不作为关联证据 |
| 关键词 | 在 SQLite 的已脱敏 summary 中做连续子串匹配；英文字母忽略大小写；跨全部匹配记录查询后才分页，每页 50 条 |
| 来源 | Logger 的完整来源名精确匹配，不是前缀或模糊匹配 |
| 筛选组合 | 范围、级别、来源、时间和关键词同时生效；提交后应用 |
| 历史读取 | Session 历史索引不回填过去没有采集的运维输出 |
| 保留与摘要 | 写入时清理超过 7 天的记录，定期按约 256 MiB 预算裁剪；单条摘要最多 8 KiB，凭据已脱敏。超出摘要、已脱敏或已清理的文字无法搜索 |

## 本轮改动

- 所有执行轮次统一为“第1轮”、步骤为“第1步”，覆盖下拉框、执行列表、概况、步骤节点、流式状态和请求标题。内部日志字段与真实模型/工具名称保持原样。
- 运维日志增加持续可见的用途说明、可展开的采集/匹配规则。来源和关键词字段分别提示精确匹配、摘要范围。
- 会话视图也可以明确选择“全部运维日志（跨会话）”或“未关联会话的日志”；没有把全局日志伪装成当前会话日志。
- 统计当前关联范围的记录数，不受关键词等筛选影响；空范围同时提示已有未关联日志并提供入口。入口清空之前的筛选，直接展示记录。
- 区分“当前范围未采集到运维日志”和“没有日志符合当前筛选条件”，提供清空筛选；级别显示为中文。
- 执行链搜索也明确只筛当前页的名称和 180 字符以内预览，不声称支持完整正文检索。

## 验收方式

合成 Logger 检查三种采集级别、debug 排除、明确元数据关联、不从正文猜测关联。数据库测试覆盖中文/英文子串、特殊字符按字面匹配、来源精确匹配、跨页查找、范围计数和空范围。原生浏览器检查真实筛选请求、中文轮次/步骤、无记录/未命中两种空状态、未关联及全局入口、清空筛选和窄屏；部署后只读检查实际历史与实际运维日志。

部署后的复查记录为全局 132 条、会话范围 0 条、未关联会话 132 条；从现存真实摘要提取关键词后查询可命中，页面入口也可正常查看。记录数会随运行增长，详见 [实际环境记录](verification/installed-history.json)。

没有为本轮优化发起新的真实模型、工具或子 Agent 调用；没有新增会话正文全文索引或改变运维日志的采集级别/保留策略。

使用宿主 RC.2 原生 JSONL 读取器验证全部拼接压缩帧：75 条会话事件，9 次模型请求和 10 次工具结果均完整，未找到失败尝试或工具错误；派生索引水位为 74，与原始事件末尾一致，原文件 hash 未改变。该会话的数据库计数和接口返回均为 0 条关联运维日志。截图时的 143 条未关联记录主要是 MCP 重连诊断及 Web 服务输出，摘要中也没有该会话 ID，不能据此归属到当前会话。记录数量随运行继续变化。

结论：0 条符合当前采集口径；它的准确含义是“未保存可明确关联到此会话的运维诊断”。不能解释为没有执行记录，也不能证明插件启用前没有产生任何运维输出。健康绿点仅表示当前采集器状态，不代表对历史运行时段有完整覆盖。即使新会话正常完成，也不保证产生诊断日志；常规模型/工具记录应查看执行列表。

本次为只读排查，未修改插件、未重启服务、未调用模型。证据见 [专项复查记录](verification/target-session-log-audit.json)。
