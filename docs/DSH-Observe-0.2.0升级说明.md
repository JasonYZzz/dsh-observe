# dsh-observe 0.2.0：请求检查工作台

本轮根据用户对真实请求信息和交互的反馈升级。参考本机 `dsh-context@0.72.0` 的 Context Browser、原生 `@deepseek-ai/dsh-client-ui-trajectory@0.2.0-rc.2` 的执行顺序和请求检查器，保留 DSH 原生主题与组件。

## 发现的问题

旧版入口以大面积筛选表单、原始 ID 和运维日志为主；历史发现隐藏在 ID 输入中；节点详情更像元数据清单。后端只返回元数据，即使原生日志已有 Prompt、工具参数和结果，也无法在观测页查看。用户难以沿着一次真实请求排查问题。

## 升级行为

- 全局会话导航复用原生 `useSessions`，展示标题、目录、时间并支持搜索，点击后才准备该会话历史。
- 执行概览和运维日志分开，过滤器与健康状态作为次级操作，减少首次使用负担。
- 执行链按源事件顺序分页，展示模型/工具类型、真实内容预览、状态、耗时与相对时间段；选择节点时检查器打开输入/输出。
- 检查器包含输入/输出、请求上下文、工具定义、源事件与日志。用户输入、工具参数/结果和模型正文直接可见，更多历史消息与工具 schema 按需展开。
- `requests.get` 定位原生请求边界，通过该边界之前的 `foldSurface` 重建模型可见上下文，避免用压缩后的当前上下文替代历史上下文。
- `content.get` 只读原生事件，先脱敏后分页；长正文可查看后续页，显示总字符数及 200 万字符显示预算，避免静默丢掉原始内容。
- 旧的六个端点及 schema 2 继续保留，不删除日志或身份绑定，不修改原生 Session。

## 真实性与内容边界

“原生日志重建的模型可见上下文”具有明确边界。它不包含宿主未记录的提供方 HTTP headers 或 adapter 最终传输体。自定义历史消息投影无法解释时，显示无法重建并提供原始事件查看，不把不完整结果冒充精确输入。

本地用户已通过原生 operator 认证后可以显式查看正文；凭据、Cookie、Authorization、replayState、带密钥的 JSON 参数均继续脱敏。二进制 data URI 不展开。正文只读与分页不调用模型或重跑工具。

## 验证与交付

检查器增加用户/system 上下文、工具 schema、参数/结果配对、重试边界、历史 surface、长正文翻页及脱敏测试。浏览器回归使用合成原生事件；另在已安装宿主中检查已有真实历史。没有为验证主动发起模型调用。

候选包、精确检查阶段和版本信息见 `verification/`；安装方法见根目录 README。0.1.0 的验收凭据保存在 `verification/0.1.0/`。
