# dsh-observe 0.2.1 消息标签优化

针对消息头部直接显示 `user / user-approval` 的问题，统一使用「系统」「用户」「上下文」「助手」「工具」「事件」标签，保持原有执行链与检查器布局。

- 以原生消息角色和 source.kind 分类，与 RC.2 Trajectory 对齐。只有明确的 user 来源归为用户；运行环境、审批设置、技能目录等 user/developer 协议消息归为上下文，未知来源不猜测为人工输入。
- 已知来源用中文说明，例如「上下文 · 审批设置」「上下文 · 运行环境」「系统 · 系统提示词」。支持原生 form 的通知、目录、状态快照等补充标签。
- 本次用户输入不再混入审批或环境信息；新增的上下文注入分组默认折叠正文。消息来源仍可展开查看协议角色、来源类型和内容形式，保留 seq 定位。
- 请求上下文筛选同步中文化，提供完整类型计数；服务端先按类型筛选再分页，避免仅筛选当前页而漏掉历史消息。

不修改历史会话、消息正文或数据库 schema；读取沿用既有鉴权、脱敏及分页。中文与英文界面使用同一套分类。

验收包括带审批、环境、技能目录的原生合成日志、未知来源、跨页筛选、浏览器标签/分组/来源查看，以及实际历史的只读检查。没有发起新的模型调用。
