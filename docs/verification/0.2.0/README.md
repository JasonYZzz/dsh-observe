# dsh-observe 0.2.0 验收记录

日期：2026-10-16。候选包已升级并安装到用户正在使用的 Web profile；DSH Web 仍监听 `127.0.0.1:3080`。保留既有插件声明、schema 2、日志与身份绑定，未发布 npm 或提交 Git。

## 本轮交付

参考本机 `dsh-context@0.72.0` 的 Context Browser 和原生 RC.2 Trajectory，改为会话导航、执行链与请求检查器。原生 `useSessions` 提供会话标题、目录和排序，选中会话后才准备历史正文。

检查器包含输入/输出、请求上下文、工具定义、源事件和关联日志。模型节点提供单次用量，工具节点直接提供参数和结果；长正文按需分页。原来的大型筛选表单、空身份字段和全局运维日志移到次级位置。详细变更见 [升级说明](../../DSH-Observe-0.2.0升级说明.md)。

## 已有真实历史检查

[installed-history.json](installed-history.json) 记录在用户现有宿主中只读检查的结果，不保存用户 Prompt、工具正文、会话 ID 或模型凭据。抽查的一次真实请求可重建 **5 条上下文消息**，找到 **37 个当时生效的工具定义**，且模型输出及工具参数/结果均可读取。原生会话标题搜索正常；插件版本为 0.2.0，采集队列、缺口、丢弃日志、失败索引均为 0。

这项检查只读取已经存在的真实执行；没有主动发起新的模型、工具或子 Agent 调用。隔离浏览器测试仍使用合成 Session 事件，不能将其标记为真实工具执行。

## 重要边界

- 上下文来自所选请求之前的原生 `foldSurface`，包含当时可见消息及生效工具定义。它不代表没有被记录的提供方 HTTP headers 或 adapter 最终传输体。
- 自定义历史消息投影无法解释时，标记无法重建，并保留原始事件查看；压缩摘要不冒用前一次普通模型请求的输入/输出。
- 正文先脱敏后分页，每页 16,384 字符；序列化使用 200 万字符预算，以及深度、字段和数组长度限制。这个预算不是进程内存上限。二进制 data URI 和 replayState 不展开。
- 凭据字段、Bearer、常见密钥和 URL 参数会脱敏；无法保证识别任意自然语言中的秘密。正文不进入派生 SQLite，不外发。
- 原生 Query 仍可能先解码完整历史。十万事件边界和串行索引不能保证极端大正文的峰值内存。
- 新的真实模型调用、实际并行工具/子 Agent 执行和端到端额外耗时仍按先前指示留待配置后验收；没有声称适配其他 RC 或企业多租户权限。

## 复现与回退

```sh
npm ci
npm run check
npm test
npm run verify:host
npm run test:web
npm pack --pack-destination dist
```

浏览器验证需要 Chromium，可通过 `DSH_TEST_CHROME` 指定已有可执行文件。当前安装位于 `~/.dsh/profiles/web`，安装前 package/lock/workspace 文件已备份在本机忽略的 `.test-results/upgrade-0.2.0-*/` 中。旧的 `0.1.0` tarball 保留在 `dist/`。回退时正常停止 Host、安装旧包并重启；本轮没有升级数据库 schema。

安装、内容策略、可信身份接口和卸载方法见 [项目 README](../../../README.md)。
